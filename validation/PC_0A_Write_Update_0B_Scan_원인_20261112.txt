확인 결과 (2026-11-12)

실제 연결된 보드
0A : Serial 26J07-0021 / Init 4729D1C4 / 검색 슬롯 0
0B : Serial 26I16-0002 / Init AEBE9602 / 검색 슬롯 0
0C : Serial 26I16-0003 / Init FB3D8E91 / 검색 슬롯 14
0D : Serial 26I16-0004 / Init E13173F1 / 검색 슬롯 9

재현한 PC Scan 결과
0A : Serial 26H06-0000 / Init 06289000 (실제 존재하지 않는 정보)
0C / 0D : 실제 정보와 일치
0B : 목록에서 누락

원인 순서
1. 0A와 0B가 모두 Scan 슬롯 0에 응답한다.
2. 두 보드가 동시에 응답하여 데이터가 충돌하고 수신 오류가 발생한다.
3. PeakLINGateway는 오류를 IsValid=false로 표시하지만, FormUDS.Gateway_FrameReceived와 UDSProtocol.Decoder는 이 값을 확인하지 않고 데이터를 해석한다.
4. 충돌한 데이터가 형식 검사를 통과하여 잘못된 0A 정보로 목록에 등록된다. Init 06289000은 4729D1C4 AND AEBE9602와 일치한다.
5. PC Write는 이 잘못된 Init으로 대상 지정 요청을 보내므로 응답이 없다.
6. 업데이트도 같은 잘못된 Init으로 대상 선택을 시도하며 UDS 31 응답 없음 (3회)로 실패한다. 이 재현에서는 Boot 진입 및 펌웨어 전송 전 단계에서 실패했다.

검증 범위
- 기존 PC의 Scan 반복문, SendService, UDS Decoder, 대상 Write 요청 생성 및 SelectUpdateTarget 코드를 임시 콘솔 실행기로 실제 LIN 버스에 연결해 재현했다.
- 실제 0A 고유번호 4729D1C4로는 제품정보 Read와 업데이트 대상 선택이 성공했다.
- 현재 값 그대로의 실제 0A Write는 앞선 검사에서 3회 성공했다. 다른 설정값으로 변경하거나 Flash에 새 값을 저장하는 시험은 하지 않았다.
- 잘못 검색된 고유번호를 사용한 Write 요청의 응답 없음과 업데이트 대상 선택 실패를 재현했다.
- PC GUI를 조작하지 않았다. 프로젝트 소스, 의자 ID, 시리얼, 펌웨어는 변경하지 않았다.
- 네 보드 제품정보를 종료 시 다시 읽어 변경되지 않았음을 확인했다.
